Cromo is a general-purpose, compiled programming language. It has the syntax of C and C++, no pointers and no garbage collector: every value has one owner, and resources are released by destructors when their owner goes out of scope, as with RAII in C++. The compiler checks ownership with a few rules that fit in a page, and LLVM optimizes the code.

The aim is a language that is **simple**, **safe enough**, and that comes with what a program needs, for three kinds of programs: **backends**, with tasks, HTTP, TLS and JSON; **apps** with windows, for the desktop and for Android from the same code; and **tools** for the command line, in one executable without dependencies.

Cromo brings together ideas that have proven themselves in other languages:

- the **syntax**, the constructors and the **destructors** of C and C++;
- **ownership checked by the compiler**, as in Rust, with references only as parameters, so that no lifetimes need to be written;
- **lightweight tasks and channels**, as in Go, without `async` and `await`;
- **one tool** that builds, runs, tests and formats, as in Go and Zig;
- the **LLVM** optimizer and linker, used by Clang, Rust and Swift.

```cromo
import std.thread

struct Account {
    string owner
    i64 balance

    Account(move string name) {
        owner = move name
    }

    ~Account() {  // runs when the account goes out of scope
        println("closing {}: {}", owner, balance)
    }

    void deposit(i64 amount) {
        balance += amount
    }
}

void pay(ref Account from, ref Account to, i64 amount) {  // ref: both change
    if (from.balance < amount) {
        throw Error(format("{} cannot pay {}", from.owner, amount))
    }
    from.balance -= amount
    to.deposit(amount)
}

i32 main() {
    Account anna = Account("Anna")
    Account bruno = Account("Bruno")
    anna.deposit(100)
    try {
        pay(ref anna, ref bruno, 30)
        pay(ref anna, ref bruno, 500)
    } catch (Exception e) {
        println("error: {}", e.message())
    }

    // Ten thousand lightweight tasks on a few threads of the system.
    thread.Atomic<i64> total
    thread.Group tasks
    for (i64 i = 1; i <= 10000; i++) {
        tasks.start([i, total]() { total.add(i) })
    }
    tasks.wait()
    println("total {}", total.load())
    ret 0
}  // bruno, then anna: destroyed in reverse order
```

## Features

- **Memory safety without a garbage collector.** No pointers, no `null`, no uninitialized values. Bounds are checked, integer overflow stops the program in debug builds, and two `ref` arguments of a call can never be the same object.
- **Visible costs.** A parameter is read, modified with `ref` or taken with `move`, and the call says which. Values that own memory are copied by `=`, as in C++, with their `copy()`, and handed over for free with `move`.
- **Types.** Structs with constructors and destructors, enums with data and an exhaustive `switch`, interfaces, and generics constrained by interfaces and checked once, at their definition.
- **Errors.** Exceptions with `try`, `catch` and `finally`. A panic, an uncaught exception and a stack overflow print a stack trace, also in release builds.
- **Concurrency.** Threads, lightweight tasks, channels, atomics, and a mutex whose data are reached only while it is locked. The compiler checks what threads and tasks share.
- **Standard library.** Files, processes, dates and time zones, logs, regular expressions in linear time, TCP and UDP, TLS 1.2 and 1.3, cryptography, JSON generated by the compiler, JSON Web Tokens, an HTTP client and server, gzip, zip and tar, WebSocket, and databases, with SQLite inside the program and a client of PostgreSQL.
- **Windows and apps.** `std.gui` draws windows and components itself, inside the program, with the colors of the program as a palette, the camera and the sensors of motion, and `cromo design` to compose a window with the mouse; flat and quiet with an ochre accent, light or dark, the same on Windows and Linux, tables of millions of rows, rich text with pieces that the user clicks, tabs, menus and tooltips, the dialogs of the files of the system, and a canvas on which the program draws, with SVG images: buttons, text boxes, lists that scroll, dialogs, app bars and the icons of Lucide. The same program is an app for Android: `cromo build --target android` writes the APK, and `cromo run --target android` runs it on a phone. `embed("logo.png")` puts a file in the program.
- **Tooling.** One executable, `cromo`, with `build`, `run`, `test` and `fmt`, a language server and an extension for Visual Studio Code.
- **Self-contained.** Programs do not depend on the C runtime. `cromo` compiles and links for Windows x64, Linux x64, Linux ARM64 and Android from either system, without a C compiler or an SDK.

## Getting started

Install Cromo for your user, without administrator rights:

```powershell
irm https://cromolang.org/install.ps1 | iex          # Windows
```

```sh
curl -sSf https://cromolang.org/install.sh | sh     # Linux
```

The archives, their SHA-256 and the way to install them by hand are on [the download page](https://cromolang.org/download/).

Then:

```sh
cromo run hello.cro          # compiles and runs
cromo build hello.cro        # writes the executable
cromo build --release        # main.cro of this folder, optimized
cromo test                   # runs the [[test]] functions
cromo fmt .                  # formats the code
cromo update                 # installs the latest version
```

The [Cromo Guide](https://cromolang.org/book/) teaches the language step by step. To build the compiler from source, see [BUILD.md](BUILD.md).

## Status

Cromo is young: its versions are 0.x, the language can still change before 1.0, and many names of the standard library are drafts. It is ready to be tried and criticized, not yet to be relied on. Every design choice is recorded, with its reasons, in [docs/decisions.md](docs/decisions.md).

- **What is safe and what is not.** [What Cromo checks, and what it does not](https://cromolang.org/book/en/appendix-safety.html) lists the guarantees, their limits and their price. The rules are not formally proven, and the compiler is young: a program without `import unsafe` that corrupts memory is a bug to report.
- **Systems.** Windows x64 and Linux x64, and from either one programs for Linux ARM64 and Android. Not yet macOS and iOS.
- **The compiler** is written in C++ and uses LLVM 23. A compiler written in Cromo will follow, once the language is mature; its first part, the formatter, is in [compiler/](compiler/).

## How Cromo is made

Cromo is designed by one person, Andrea Masullo, and written with an AI assistant: vibe coding, with rules. The author takes every design decision, and each one is written in [docs/decisions.md](docs/decisions.md) with its reasons before the code that needs it; the assistant writes most of the code of the compiler, of the library and of the guide. What keeps the result honest is that it is checked by programs and not by trust: more than 450 tests, run for each system, and every example of the guide compiled and run when the guide is built.

## Contributing
