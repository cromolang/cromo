# JSON

JSON is how most services exchange data. In Cromo, the compiler writes the conversion between a struct and JSON by itself, the first time it is needed: no annotation is required on the struct, no code is generated by a separate tool, and the conversion is as fast as code written by hand. The module is [std.json](std.json.html).

## From structs to JSON and back

```cromo
import std.json

struct Address {
    string city
    string country
}

struct Person {
    string name
    i64 born
    list<string> languages
    Address address
}

i32 main() {
    Person p
    p.name = "Grace"
    p.born = 1906
    p.languages = ["COBOL", "FLOW-MATIC"]
    p.address.city = "New York"
    p.address.country = "USA"

    string text = json.encode(p)
    println("{}", text)

    Person back = json.decode<Person>(text)
    println("{} was born in {}", back.name, back.born)
    ret 0
}
```

```output
{"name":"Grace","born":1906,"languages":["COBOL","FLOW-MATIC"],"address":{"city":"New York","country":"USA"}}
Grace was born in 1906
```

- `json.encode(value)` writes compact JSON; `json.pretty(value)` writes it on several lines, indented.
- `json.decode<T>(text)` reads a `T` from its text.
- A struct is an object with a member for each field, in the order of the fields.

## The types that can be converted

The compiler converts these types, with no declaration:

| Type | In JSON |
|---|---|
| `i8` ... `i64`, `u8` ... `u64` | a number without a point |
| `f32`, `f64` | a number |
| `bool` | `true` or `false` |
| `string` | a string |
| `list<T>` | an array |
| `T[n]`, a fixed array | an array of exactly `n` elements |
| `map<string, T>` | an object |
| an enum | the name of its case, or an object for a case with data |
| a struct, generic ones too | an object with a member for each field |
| `json.Value` | any value of JSON |

The elements, the values and the fields must be of these types too. A field that cannot be converted, as a function, is a compile error that names it and its type, at the call that needs the conversion:

```cromo error
import std.json

struct Job {
    string name
    func() run
}

i32 main() {
    Job job
    println("{}", json.encode(job))
    ret 0
}
```

```output
error: values of type Job cannot be converted to JSON
```

The whole message ends with `Job.run has type func()`. A map whose keys are not strings, as `map<i64, string>`, is an error too: the names of the members of JSON are strings.

## Writing JSON

`json.encode` writes everything on one line, without spaces; `json.pretty` indents by two spaces for each level, with a space after each `:`:

```cromo
import std.json

struct Shop {
    string name
    map<string, i64> stock
    f64[2] position
    list<string> tags
}

i32 main() {
    Shop shop
    shop.name = "Corner"
    shop.stock["pears"] = 4
    shop.stock["apples"] = 10
    shop.stock["Bananas"] = 2
    shop.position[0] = 45.5
    println("{}", json.encode(shop))
    println("{}", json.pretty(shop))
    ret 0
}
```

```output
{"name":"Corner","stock":{"Bananas":2,"apples":10,"pears":4},"position":[45.5,0.0],"tags":[]}
{
  "name": "Corner",
  "stock": {
    "Bananas": 2,
    "apples": 10,
    "pears": 4
  },
  "position": [
    45.5,
    0.0
  ],
  "tags": []
}
```

- The keys of a map are sorted by their bytes, so uppercase before lowercase: the text does not change with the order of the map.
- All the fields are written, also those that are not `public`, as `copy()` copies them all. `[[json(skip)]]`, below, leaves one out.
- An empty list is `[]`, an empty map `{}`.

The numbers and the strings:

```cromo
import std.json

i32 main() {
    list<f64> numbers = [1.0, 0.1, 1.0 / 3.0, 1e20, 0.000001]
    println("{}", json.encode(numbers))
    println("{}", json.encode("quote \", tab \t, accent é, slash /"))
    f64 zero = 0.0
    try {
        json.encode(zero / zero)
    } catch (Exception e) {
        println("{}", e.message())
    }
    ret 0
}
```

```output
[1.0,0.1,0.3333333333333333,1e+20,1e-06]
"quote \", tab \t, accent é, slash /"
cannot encode JSON: nan is not a number of JSON
```

- A float is written with the shortest text that reads back the same number, with `.0` when it is integral, so that it is read back as a float.
- NaN and the infinities are an exception: JSON has no way to write them.
- A string is escaped only where JSON requires it: `"`, `\` and the control characters. The other characters, accented letters and emoji too, are written as they are, in UTF-8.

## Reading JSON

`json.decode<T>` starts from the default value of `T`, then fills it with what the text has:

- A member that is missing leaves the field with the value it has in the default value of the struct: its initial value, if it has one.
- A member that is `null` gives the default value of the type of the field: 0, `""`, `false`, an empty list, the first case of an enum. The same holds for the elements of a list and the values of a map.
- A member without a field is ignored.
- Of a member written twice, the last one wins.

```cromo
import std.json

struct Settings {
    i64 retries = 3
    string mode = "fast"
    list<string> hosts
}

i32 main() {
    Settings a = json.decode<Settings>("{\"hosts\": [\"alpha\", null], \"debug\": true}")
    println("{}", json.encode(a))
    Settings b = json.decode<Settings>("{\"retries\": null, \"mode\": null}")
    println("{}", json.encode(b))
    Settings c = json.decode<Settings>("{\"retries\": 1, \"retries\": 2}")
    println("{}", c.retries)
    ret 0
}
```

```output
{"retries":3,"mode":"fast","hosts":["alpha",""]}
{"retries":0,"mode":"","hosts":[]}
2
```

There are no optional values in Cromo, so a `null` cannot be kept in an `i64`: a program that must tell a `null` apart from a value declares the field `json.Value`, as shown below.

### Numbers

An integer field takes only an integer of JSON that fits in its type: `1.0` and `1e3` are floats, as in Go. A float field takes an integer too. A `u64` reads all its digits, up to 2^64 - 1.

```cromo
import std.json

struct Reading {
    i8 level
    i64 count
    u64 serial
    f64 ratio
}

void show(string text) {
    try {
        Reading r = json.decode<Reading>(text)
        println("ok: {}", json.encode(r))
    } catch (Exception e) {
        println("{}", e.message())
    }
}

i32 main() {
    show("{\"ratio\": 2, \"serial\": 18446744073709551615}")
    show("{\"count\": 2.0}")
    show("{\"level\": 300}")
    show("{\"serial\": -1}")
    ret 0
}
```

```output
ok: {"level":0,"count":0,"serial":18446744073709551615,"ratio":2.0}
cannot decode JSON: at count: expected an integer, found a float
cannot decode JSON: at level: 300 does not fit in i8
cannot decode JSON: at serial: -1 does not fit in u64
```

### Fixed arrays

A fixed array takes an array of JSON with exactly its number of elements; another length is an error that says both:

```cromo
import std.json

i32 main() {
    i32[3] rgb = json.decode<i32[3]>("[255, 128, 0]")
    println("{} {} {}", rgb[0], rgb[1], rgb[2])
    try {
        i32[3] short = json.decode<i32[3]>("[255, 128]")
    } catch (Exception e) {
        println("{}", e.message())
    }
    ret 0
}
```

```output
255 128 0
cannot decode JSON: expected an array of 3 elements, found 2
```

### A strict reader

The text must be JSON as RFC 8259 defines it: no comments, no comma after the last element, strings in double quotes, and nothing after the value but spaces. The arrays and objects can be nested up to 512 levels, so that a hostile text cannot use up the stack. A text that is not JSON is an exception with the line and the column:

```cromo
import std.json

void show(string text) {
    try {
        json.Value v = json.parse(text)
        println("ok: {}", json.encode(v))
    } catch (Exception e) {
        println("{}", e.message())
    }
}

i32 main() {
    show("[1, 2]")
    show("[1, 2,]")
    show("{'a': 1}")
    show("// a comment\n[1]")
    show("{\"a\": 1}\n{\"b\": 2}")
    show("\"\\ud800\"")
    show("[".repeat(600))
    ret 0
}
```

```output
ok: [1,2]
cannot read JSON: line 1, column 7: expected a value
cannot read JSON: line 1, column 2: expected the name of a member, in double quotes
cannot read JSON: line 1, column 1: expected a value
cannot read JSON: line 2, column 1: the text goes on after the value
cannot read JSON: line 1, column 8: the first half of a pair of \u escapes comes without the second
cannot read JSON: line 1, column 513: the arrays and objects are nested more than 512 times
```

A `\u` escape for half of a character outside the first 65536, without its other half, is an error too: it is not a character.

## Names and fields to skip

The attribute `[[json(...)]]` before a field changes its name in JSON, or leaves it out. It can be on the line of the field or on its own line before it:

```cromo
import std.json

struct Account {
    [[json("user_id")]] i64 id
    string name
    [[json(skip)]]
    string password = "unset"
}

i32 main() {
    Account a
    a.id = 7
    a.name = "Ada"
    a.password = "secret"
    println("{}", json.encode(a))

    Account b = json.decode<Account>("{\"user_id\": 8, \"name\": \"Grace\", \"password\": \"x\"}")
    println("{} {} {}", b.id, b.name, b.password)
    ret 0
}
```

```output
{"user_id":7,"name":"Ada"}
8 Grace unset
```

A field with `skip` is neither written nor read: it keeps its default value. The compiler checks the attributes:

```cromo error
struct Account {
    [[json("id")]] i64 id
    [[json("id")]] i64 owner
    [[json(hidden)]] string password
    [[secret]] string token
}

i32 main() {
    ret 0
}
```

```output
error: another field of Account has the name 'id' in JSON
error: json takes the name of the field in JSON, as json("user_id"), or skip, as json(skip)
error: unknown attribute 'secret': for now there is only json
```

## Enums

A case without data is written as its name; a case with data as an object whose only member is the case, with its data as the members of a struct. `[[json("name")]]` before a case gives it another name:

```cromo
import std.json

enum Shape {
    Empty
    Circle(f64 radius)
    [[json("rect")]] Rectangle(f64 width, f64 height)
}

i32 main() {
    list<Shape> shapes = [Shape.Empty, Shape.Circle(2.5), Shape.Rectangle(1.0, 2.0)]
    string text = json.encode(shapes)
    println("{}", text)
    list<Shape> back = json.decode<list<Shape>>(text)
    println("{:?}", back[2])
    ret 0
}
```

```output
["Empty",{"Circle":{"radius":2.5}},{"rect":{"width":1.0,"height":2.0}}]
Rectangle(1.0, 2.0)
```

Reading an enum:

- A case without data must be a string, its name; a case with data an object with exactly one member, the case.
- A member of the data that is missing, or `null`, gives the default value of its type.
- A `null` in place of the enum gives its first case.
- Another name, or another kind of value, is an error that lists the names.

```cromo
import std.json

enum Shape {
    Empty
    Circle(f64 radius)
    [[json("rect")]] Rectangle(f64 width, f64 height)
}

void show(string text) {
    try {
        Shape s = json.decode<Shape>(text)
        println("ok: {:?}", s)
    } catch (Exception e) {
        println("{}", e.message())
    }
}

i32 main() {
    show("{\"rect\": {\"width\": 3}}")
    show("null")
    show("\"Square\"")
    show("{\"Circle\": {\"radius\": 1}, \"Empty\": {}}")
    ret 0
}
```

```output
ok: Rectangle(3.0, 0.0)
ok: Empty
cannot decode JSON: expected one of Empty, Circle, rect, found "Square"
cannot decode JSON: expected an object with one member, the case, found an object
```

A case has only the attribute `json("name")`, not `skip`: a value of the enum must always have a name to be written with. Two cases with the same name in JSON are an error.

## Values of any shape: json.Value

When the shape of the data is not known in advance, `json.parse(text)` gives a `json.Value`, an enum with a case for each kind of value of JSON:

| Case | For |
|---|---|
| `Null` | `null` |
| `Bool(bool value)` | `true`, `false` |
| `Int(i64 value)` | an integer that fits in an `i64` |
| `UInt(u64 value)` | an integer from 2^63 to 2^64 - 1 |
| `Float(f64 value)` | a number with a point or an exponent, or an integer too large for the others |
| `Text(string value)` | a string |
| `Array(list<json.Value> items)` | an array |
| `Object(list<json.Member> members)` | an object: a `json.Member` has `name` and `value` |

Integers and floating-point numbers are kept apart, so an identifier of 64 bits keeps all its digits. An object keeps its members in their order, also two with the same name.

The methods read a value without a `switch`:

| Method | Gives |
|---|---|
| `isNull()` | whether the value is `null` |
| `asBool()` | the `bool` of a `Bool` |
| `asInt()` | the `i64` of an `Int`; not of a `Float` as `2.0`, nor of a `UInt` |
| `asFloat()` | an `f64` from a `Float`, an `Int` or a `UInt`; above 2^53 an integer can lose its last digits |
| `asText()` | a copy of the string of a `Text` |
| `len()` | the number of elements of an array, or of members of an object |
| `has(name)` | whether the value is an object with that member; `false` for the other kinds |
| `get(name)` | a copy of the member of an object; with the same name twice, the last one |
| `at(index)` | a copy of the element of an array, from 0 |
| `keys()` | the names of the members of an object, in their order |
| `set(name, value)` | changes the member of an object, or adds it at the end |
| `add(value)` | adds an element at the end of an array |

`json.object()` and `json.array()` give an empty object and an empty array, to fill with `set` and `add`. A method used on the wrong kind of value, a missing member and an index out of the array are exceptions, not panics: the data come from outside.

```cromo
import std.json

i32 main() {
    json.Value v = json.parse("{\"items\": [1, 2.5, \"x\", null], \"ok\": true, \"id\": 18446744073709551615}")
    json.Value items = v.get("items")
    println("{} items, the first is {}", items.len(), items.at(0).asInt())
    println("{} {} {}", items.at(2).asText(), items.at(3).isNull(), v.get("ok").asBool())
    println("{:?} {}", v.keys(), v.has("name"))
    println("{:?}", v.get("id"))

    switch (items.at(1)) {
        case Int(i64 n) {
            println("an integer: {}", n)
        }
        case Float(f64 f) {
            println("a float: {}", f)
        }
        default {
            println("something else")
        }
    }

    try {
        v.get("name")
    } catch (Exception e) {
        println("{}", e.message())
    }
    try {
        items.at(2).asInt()
    } catch (Exception e) {
        println("{}", e.message())
    }

    json.Value made = json.object()
    made.set("language", json.Value.Text("Cromo"))
    made.set("version", json.Value.Int(27))
    json.Value tags = json.array()
    tags.add(json.Value.Text("fast"))
    tags.add(json.Value.Bool(true))
    made.set("tags", tags)
    println("{}", json.encode(made))
    ret 0
}
```

```output
4 items, the first is 1
x true true
["items", "ok", "id"] false
UInt(18446744073709551615)
a float: 2.5
the object of JSON has no member 'name'
the value of JSON is a string, not an integer
{"language":"Cromo","version":27,"tags":["fast",true]}
```

`set` and `add` copy the value, unless it is given with `move`.

### Between values and types

A `json.Value` converts to a type and back, with the same rules as the text:

- `json.toValue(x)` gives the `json.Value` of `x`, the same that `json.parse(json.encode(x))` gives: a program can add members to it before writing it.
- `json.fromValue<T>(v)` reads a `T` from a value, as `json.decode<T>` reads it from a text.

A field of type `json.Value` takes any value, as it is. It is the way to tell a `null`, or a missing member, from a value:

```cromo
import std.json

struct Patch {
    string name
    json.Value age  // null clears the age, a number sets it
}

struct Point {
    i64 x
    i64 y
}

i32 main() {
    list<string> texts = ["{\"name\": \"Ada\", \"age\": 36}", "{\"name\": \"Ada\", \"age\": null}", "{\"name\": \"Ada\"}"]
    for (string text in texts) {
        Patch p = json.decode<Patch>(text)
        if (p.age.isNull()) {
            println("{}: clear the age", p.name)
        } else {
            println("{}: the age is {}", p.name, json.fromValue<i64>(p.age))
        }
    }

    Point origin
    json.Value v = json.toValue(origin)
    v.set("label", json.Value.Text("origin"))
    println("{}", json.encode(v))
    ret 0
}
```

```output
Ada: the age is 36
Ada: clear the age
Ada: clear the age
{"x":0,"y":0,"label":"origin"}
```

A missing member leaves the field `Null`, the default value of `json.Value`, as a `null` does. A program that must tell a missing member from a `null` reads the text with `json.parse`, and asks `has(name)` of the object.

## Generic code: json.Data

`json.Data` is the interface of the types that can be converted, which they all satisfy by themselves, without declaring it. A generic function that converts its `T` says so with a constraint, as `json.encode` does:

```cromo
import std.json

struct Point {
    i64 x
    i64 y
}

string message<T : json.Data>(string kind, T value) {
    ret format("{{\"kind\":\"{}\",\"data\":{}}}", kind, json.encode(value))
}

i32 main() {
    Point p
    p.x = 3
    println("{}", message("point", p))
    println("{}", message("numbers", [i64(1), 2, 3]))
    ret 0
}
```

```output
{"kind":"point","data":{"x":3,"y":0}}
{"kind":"numbers","data":[1,2,3]}
```

Without the constraint, the compiler does not know that `T` can be converted ([Interfaces and generics](interfaces-generics.md) explains the constraints):

```cromo error
import std.json

string send<T>(T value) {
    ret json.encode(value)
}

i32 main() {
    println("{}", send(1))
    ret 0
}
```

```output
error: T can be converted to JSON only with a constraint: write <T : json.Data>
```

## Errors

A text that is not JSON, or JSON that does not fit the type, is an exception that says where: the line and the column for the text, the path of the value for the conversion.

```cromo
import std.json

struct Point {
    i64 x
    i64 y
}

struct Drawing {
    list<Point> points
}

i32 main() {
    try {
        Drawing d = json.decode<Drawing>("{\"points\": [{\"x\": 1, \"y\": 2}, {\"x\": 1, \"y\": \"two\"}]}")
    } catch (Exception e) {
        println("{}", e.message())
    }
    try {
        Point p = json.decode<Point>("[1, 2]")
    } catch (Exception e) {
        println("{}", e.message())
    }
    try {
        json.Value v = json.parse("{\"x\": 1,, }")
    } catch (Exception e) {
        println("{}", e.message())
    }
    ret 0
}
```

```output
cannot decode JSON: at points[1].y: expected an integer, found a string
cannot decode JSON: expected an object, found an array
cannot read JSON: line 1, column 9: expected the name of a member, in double quotes
```

## Summary

- `json.encode`, `json.pretty` and `json.decode<T>` convert numbers, strings, lists, fixed arrays, maps with string keys, enums and structs, with code written by the compiler; a field that cannot be converted is a compile error.
- Writing: the fields in their order, the keys of the maps sorted, floats with the shortest text and `.0`, no NaN nor infinity, only the escapes that JSON needs.
- Reading: strict JSON, nested up to 512 levels; a missing member keeps the default value of the struct, a `null` gives the default value of the type, an unknown member is ignored; integers must be integers that fit.
- `[[json("name")]]` renames a field or a case; `[[json(skip)]]` leaves a field out.
- `json.parse` gives a `json.Value` for data of any shape, with `Int`, `UInt` and `Float` kept apart; `toValue` and `fromValue` convert between values and types.
- A generic function that converts its `T` writes `<T : json.Data>`.
- Errors say where the problem is: the line and the column, or the path of the value.
